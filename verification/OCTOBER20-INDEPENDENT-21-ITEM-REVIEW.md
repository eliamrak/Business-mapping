## Attrition Calculation Recommendation

The current aggregate output cannot safely supply the requested denominator. A new **derived, read-only client-level result inside the existing ending engine** is needed; no database migration or manually entered denominator is necessary. This is a proposed definition consistent with the established-three and 90-day rules, not an assertion that the candidate already implements it or that the missing original notes mandated this exact denominator.

1. Select one explicit event window `[S,E]` and scope, using the same admitted qualifying treatment visits, same-day deduplication, service classification, identity mapping, excluded-follow-up handling and observation cutoff as the existing ending calculation. Practice identities must remain distinct clients across clinicians; clinician scope uses that clinician's relationship. Do not sum clinician client counts to create practice unique clients.
2. Derive an eligible set from actual distinct visit dates: a client is established on date `d` only after at least three qualifying attended dates on/before `d`; the relationship is active on `d` only if a qualifying attended date on/before `d` is within the existing inclusive 90-day rule (`lastShow + 90 >= d`). Include a client in the period's eligible set if both conditions hold on at least one date of `[S,E]`. Preserve pre-window visits to establish state at `S`; include clients first becoming established during the window. This prevents numerator events from being excluded merely because the client was not established on the first day of the month.
3. Numerator: distinct clients from the existing validated final-treatment ending events whose event date is in that same window **and in the eligible set**. Retain the existing rule that a later qualifying return removes the earlier ending; do not silently change the engine to count recurrent 90-day gaps. A direct event-ID set is needed; a rounded monthly average multiplied by months is not evidence. Count and percentage must use exactly the same events and eligible window.
4. For a true whole-window percentage, certify complete evidence for the selected window and every required 90-day look-forward through `E+90`, plus the evidence needed for prior establishment/active state. Unknown identities, unresolved later rows, coverage gaps and left-censored establishment require a reason or withholding certification. Observed-three relationships can be calculated as an explicitly observed cohort, but cannot silently certify all actual historical clients when earlier establishment may be missing.
5. Return `{requestedWindow, effectiveWindow, endingClientIds/count, eligibleClientIds/count, coverageComplete, attritionPct, reasons}` from the shared engine. With complete matching evidence and positive eligible count, `attritionPct = 100 * uniqueEnded / uniqueEligible`; covered zero endings with a positive eligible denominator is 0%. Zero or unknown denominator yields unknown percentage. Numerator must be a subset of denominator; assert this rather than clamping a rate.
6. If the desired trailing window is not yet mature, keep **whole-window count/percentage unknown**. An optional separate `mature observed portion S to min(E, asOf-90)` may be calculated if its full coverage is established and its actual dates/count/denominator are displayed. Do not label that subset as the entire trailing period. A discontiguous union of mature full months needs the exact included months and a set-based denominator over those dates, not the nominal continuous window. Alternatively a fully lagged 3/12-month ending window would be a product definition change and must be explicitly reconciled with the original historical-period instructions.

Independent counterexample supporting step 2: three visits July 2/9/16, no later visit, complete June-November evidence, as-of November 30. The existing engine reports one mature July ending but zero established-at-July-start clients. A period denominator that includes the observed client once they become established yields one eligible client and one ending for this synthetic July window. A month-start denominator yields zero and fails. Conversely, summing the same client across three monthly start populations yields three client-months, not three unique clients. Neither existing aggregate is a substitute for derived client sets.

Required focused cases before accepting the implementation: clients established before/in the window; same-month establishment/ending; active at start then ending without an in-window visit; later return removing an ending; clients transferring clinicians; multiple providers but one practice identity; visits on inclusive day-90 boundaries; PHONE/documentation exclusion; duplicate same-day evidence; uncertain later rows; incomplete/interrupted coverage; immature tails; left censoring; covered-zero numerator; zero denominator; and equality of Overview/Team/Sessions results wherever the same metric/scope/window is requested.
